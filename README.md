# INSOU 店舗メニュー配信システム (MVP)

管理者がPDFメニューを登録して複数店舗へ公開設定を行い、店舗スタッフが自店舗向けメニューを専用ビューアで閲覧できる業務フロー検証用Webアプリケーションです。

本書で定義するMVPは [`docs/mvp-spec.md`](./docs/mvp-spec.md) に基づき、データソースとして **Google Apps Script (GAS)**、**Google スプレッドシート**、**Google ドライブ** を利用します。

---

## ⚠️ 【重要】MVPのハリボテ認証・セキュリティについて

本システムにおけるログイン機能（店舗コード入力・管理者ログイン）は、**画面遷移と業務フロー（自店舗向けメニューの切り替え・PDF閲覧）を検証するための「ハリボテ認証（モック認証）」** です。

- パスワードの暗号化保存、ハッシュ検証、JWT/セッション検証、Row Level Security (RLS) などの本番セキュリティ基盤は実装されていません。
- 本番運用で想定される認証基盤（Supabase Auth、月1回のパスワード変更、アクセス制御等）の仕様は [`docs/production-spec.md`](./docs/production-spec.md) を参照してください。

## 主な機能と特徴

### 1. 管理者機能

- **PDF登録・アップロード**: PDFファイルをGoogle Driveへ自動保存。
- **配信メニュー一覧**: 登録済みメニューの一覧確認、更新日の管理。
- **複数店舗選択**: 1つのPDFメニューを任意の複数店舗へ一括公開設定可能。
- **メニュー編集・削除**: タイトル変更、対象店舗変更、PDFファイルの差し替え、削除（Drive上のファイルもゴミ箱へ移動）。
- **店舗管理**: 配信対象店舗の追加・削除（スプレッドシートと連動）。

### 2. 店舗側機能

- **店舗端末ログイン**: 店舗コードとPIN（デモ用）を入力して自店舗画面へログイン。
- **ログイン直後表示**: 店舗ごとに割り当てられた1つのPDFメニューを一覧画面なしで直接表示。
- **Androidタブレット向けPDFビューア**:
  - カードを後ろへ回すページ切替エフェクト
  - ピンチ操作による拡大・縮小（100%〜400%）と、拡大時の指によるパン移動
  - PDFのみを表示する全画面UIと右下の控えめなページ番号
- **秘匿性・保護設計**:
  - クライアント側へ Google Drive のファイルIDや公開URLを直接露出させない設計
  - 通常のUIからPDFのダウンロードボタン・共有ボタンを排除

## 技術構成

- **フロントエンド**: Next.js (App Router), React 19, Tailwind CSS, Lucide Icons, PDF.js (`pdfjs-dist`)
- **バックエンド API**: Google Apps Script (GAS) Web App (`gas/Code.gs`)
- **データベース**: Google スプレッドシート (`stores`, `menus`, `menu_stores` シート)
- **ファイルストレージ**: Google ドライブ (PDF本体保存)

## セットアップ手順

### 1. Google側データ保存先の準備

SpreadsheetとPDF保存先は既存ファイルを使用しません。後述の `setupMvpResources` により、`INSOU_Menu_Master_MVP_日時` と `INSOU_Menu_PDFs_MVP_日時` を新規作成します。

### 2. GAS プロジェクトの作成と配置

1. 作成したスプレッドシートのメニューから **「拡張機能」 > 「Apps Script」** を開きます。
2. プロジェクト名を入力します（例: `INSOU-Menu-GAS`）。
3. 本リポジトリの [`gas/Code.gs`](./gas/Code.gs) の内容をコピーし、エディタの `Code.gs` に貼り付けます。
4. 左メニュー「プロジェクトの設定（歯車アイコン）」を開き、**「『appsscript.json』マニフェスト ファイルをエディタで表示する」** にチェックを入れます。
5. エディタに戻り、`appsscript.json` を本リポジトリの [`gas/appsscript.json`](./gas/appsscript.json) の内容で上書きします。

### 3. スクリプト プロパティの設定

左メニュー「プロジェクトの設定（歯車アイコン）」下部の **「スクリプト プロパティ」** に以下を追加します:

| プロパティ       | 値       | 説明                                          |
| ---------------- | -------- | --------------------------------------------- |
| `SPREADSHEET_ID` | 設定不要 | 新規作成したSpreadsheetのIDが自動設定されます |
| `PDF_FOLDER_ID`  | 設定不要 | 新規作成したPDF保存先のIDが自動設定されます   |

### 4. 初期データベース（シート・シードデータ）の実行

1. GASエディタで `Code.gs` を開きます。
2. 実行関数一覧から **`setupMvpResources`** を選択して実行します。
3. 初回実行時、権限承認ダイアログが表示されるので「許可」します。
4. 新規Spreadsheetと新規PDF保存フォルダが作成され、`stores`, `menus`, `menu_stores` の3シートと初期店舗データが登録されます。

> `createNewPdfStorageFolder` を再実行すると、既存フォルダを削除せず、新しい空の保存先へ切り替わります。

### 5. Web アプリケーションとしてデプロイ

1. GASエディタ右上の **「デプロイ」 > 「新しいデプロイ」** をクリックします。
2. 種類の選択（歯車アイコン）で **「ウェブアプリ」** を選択します。
3. 以下の設定を行います:
   - **次のユーザーとして実行**: **自分**
   - **アクセスできるユーザー**: **全員 (Anyone)**
4. **「デプロイ」** をクリックし、発行された **ウェブアプリ URL**（`https://script.google.com/macros/s/.../exec`）をコピーします。

## フロントエンドの起動方法

### 1. 環境変数の設定

プロジェクト直下に `.env.local` を作成し、GASのWebアプリURLを設定します:

```env
NEXT_PUBLIC_GAS_WEB_APP_URL="https://script.google.com/macros/s/xxxxxxxxxxxxxxxxxxxxxxxxxxxxx/exec"
```

> **※URLが未設定の場合**:
> `NEXT_PUBLIC_GAS_WEB_APP_URL` が設定されていない場合、画面上部に案内が表示され、ローカルのデモサンプルデータで画面の操作確認が可能です。

### 2. ローカルサーバー起動

```bash
npm install
npm run dev
```

ブラウザで `http://localhost:3000` を開きます。

## 画面一覧と操作方法

| 画面                          | 説明                                                                                                  |
| ----------------------------- | ----------------------------------------------------------------------------------------------------- |
| **統合ログイン**              | 店舗端末ログイン（店舗コード例: `KS-01`）または管理者ログイン（初期値でそのままログイン可能）を選択。 |
| **PDFビューア**               | 店舗ログイン直後に割り当て済みメニューを直接表示。カード切替、ピンチズーム、パン操作に対応。          |

| **新規PDF登録・編集（管理）** | PDFファイルのドラッグ＆ドロップ、タイトル設定、公開対象店舗のチェックボックス選択。                   |
| **店舗一覧・管理（管理）**    | 配信対象店舗の追加・削除。                                                                            |
