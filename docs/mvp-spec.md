# INSOU メニュー閲覧システム MVP仕様

## MVPの目的

MVPの目的は、本番環境を再現することではなく、次の業務フローが実際に成立するかを確認することである。

管理者 → PDFを登録 → 閲覧対象店舗を指定 → 保存 → 店舗側ログイン → 割り当て済みPDFを直ちに表示

特に、以下を検証する。

- 管理者が簡単にPDFを登録できるか
- 複数店舗への公開設定が分かりやすいか
- 店舗スタッフが迷わずPDFを閲覧できるか
- 店舗ごとに異なるPDFを配信する運用が成立するか

## 現在のモックアップとの関係

現在のリポジトリは、`README.md` に記載されているとおり、登録データとPDFをブラウザの `localStorage` に保存する画面・操作確認用モックアップである。

本書で定義するMVPでは、このモックアップで確認した画面と操作を引き継ぎつつ、データ連携先をGoogle Apps Script（GAS）、Google Spreadsheet、Google Driveへ移行する。したがって、現行の `localStorage` 構成はMVPの最終的な技術構成ではない。

## MVP技術構成

MVPでは以下を使用する。

- Google Apps Script（GAS）
- Google Spreadsheet
- Google Drive
- 本格的な認証基盤を使用しないハリボテログイン

### GAS

- バックエンド処理
- Spreadsheetとのデータ連携
- Google DriveとのPDF連携
- 管理画面・店舗画面とのデータ受け渡し

### Spreadsheet

簡易データベースとして使用し、主に以下を管理する。

- 店舗情報
- メニュー情報
- メニューと店舗の紐付け

### Google Drive

PDFファイル本体の保存先として使用する。SpreadsheetにはPDF本体ではなく、以下の情報を保持する。

- Drive File ID
- メニュー名
- 更新日時
- 対象店舗

## MVPで実装する機能

### 管理者側

- PDF登録
- PDF一覧表示
- メニュー名等の設定
- 閲覧対象店舗の選択
- PDF更新
- 必要に応じたPDF削除

### 店舗側

- ログイン画面
- ログイン直後に割り当て済みPDFを直接表示（一覧画面は設けない）
- PDFビューア
- カードを後ろへ送るページ切替
- Androidタブレットのピンチ拡大・縮小
- 拡大時の指によるパン移動
- PDFのみを表示する全画面UIと右下のページ表示
- 通常のUIからダウンロード・共有機能を提供しない

### 店舗別表示

店舗とメニューの紐付けをSpreadsheetで管理し、店舗ごとに閲覧できるPDFを変更可能にする。

1つのメニューを複数店舗へ公開できる一方、各店舗に有効なメニューは常に1つとする。新しいメニューを店舗へ割り当てた場合、その店舗の旧割り当ては自動解除する。

## MVPのログイン仕様

MVPでは本格的な認証機能を実装しない。ログイン画面と店舗判定の動作を確認するためのハリボテ認証とする。

確認対象は「店舗がログインした直後、その店舗に割り当てられたPDFだけが表示される」という画面・業務フローである。以下はMVP対象外とする。

- 本格的な認証基盤
- Supabase Auth
- パスワードの高度な管理
- セッションの厳密な管理
- パスワード変更機能
- 不正ログイン対策

## MVPのセキュリティ

MVPでは最低限、以下を満たす。

- 他店舗向けPDFを通常の画面から閲覧できない
- PDFダウンロードボタンを表示しない
- 共有ボタンを表示しない
- Google DriveのURLを画面上へ直接表示しない

本番レベルのセキュリティはMVPでは実装しない。

## MVPでは実装しないもの

- Supabase Authおよび本格的なログイン認証
- 月1回のパスワード変更
- Vercelを前提とした本番運用
- Supabase Database / Storage
- Row Level Security（RLS）
- Private Storage
- 本格的なアクセス制御
- PDFのアプリ内部キャッシュ、オフライン閲覧
- PWA、Service Worker
- PDFのバージョン同期、更新PDFのみの差分取得
- 本格的なセッション保持
- アクセスログ、操作ログ
- 本番バックアップ、障害監視

これらの現時点の想定は [`production-spec.md`](./production-spec.md) に記載する。
