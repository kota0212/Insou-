# INSOU メニュー閲覧システム 本番仕様（暫定）

## 重要事項

本書は正式決定した仕様ではなく、現時点で想定している本番構成案である。

技術構成、セキュリティ、運用、費用、契約、保守体制等について、VEXUM社内で正式な合意は取れていない。Next.js、Vercel、Supabaseは現時点の第一候補であり、採用は今後正式決定する。

## 現時点の本番想定構成

- Webアプリ：Next.jsを第一候補とする
- デプロイ：Vercelを第一候補とする
- バックエンド：Supabaseを第一候補とする
- Supabaseの想定機能：Database、Auth、Storage

構成イメージ：

```text
店舗 / 管理者
    ↓
ブラウザ
    ↓
Next.js Webアプリ
    ↓
Vercel
    ↓
Supabase
├ Database
├ Auth
└ Storage
```

## 本番の基本機能

MVPで確認した以下の機能を引き継ぐ想定である。

### 管理者

- PDF登録、更新、削除
- 閲覧対象店舗設定
- メニュー管理

### 店舗

- 店舗ログイン
- 自店舗用PDF一覧
- アプリ内PDF閲覧

## 本番認証

本番ではハリボテ認証を廃止する。Supabase Authを第一候補として、正式な認証基盤を導入する想定である。

必要な仕様は以下とする。

- 店舗ごとの認証
- 安全なパスワード管理
- ログインセッション管理
- アカウント無効化
- ログアウト、再認証
- 店舗ごとのアクセス制御

### パスワード運用

現時点では、店舗パスワードを月1回変更する運用を想定する。管理者による変更、自動発行、各店舗への通知方法は今後決定する。

## 本番データベース

Supabase Database（PostgreSQL）を第一候補とし、SpreadsheetではなくリレーショナルDBで管理する想定である。

### 店舗

- `store_id`
- 店舗名
- アカウント情報
- 有効 / 無効

### メニュー

- `menu_id`
- メニュー名
- `file_path`
- `version`
- `updated_at`
- 公開状態

### 店舗・メニュー紐付け

- `store_id`
- `menu_id`

## PDF保存

Supabase Storageを第一候補とする。PDF本体はDatabaseではなくStorageへ保存する。

原則としてPrivate Storageを使用し、PDFを一般公開URLとして公開しない想定である。認証と店舗権限を確認した上でPDFを取得する。

## PDFの共有・取り出し制御

求めるセキュリティレベルは「一般的なユーザー操作ではPDFファイルを取り出したり、他者へ共有・転送しにくい状態」とする。

- PDFダウンロードボタンを設けない
- ファイル保存ボタンを設けない
- 共有ボタンを設けない
- 外部アプリで開くボタンを設けない
- Storageの公開URLを直接表示しない

スクリーンショットや高度な技術による抽出を完全に防ぐことは、現時点では要件に含めない。

## 店舗ごとのアクセス制御

本番ではフロントエンド上の表示制御だけでなく、Database / Storage側でもアクセスを制御する。

Supabaseを採用する場合は、Row Level Security（RLS）やStorage Policy等を利用し、店舗Aが店舗B向けPDFへアクセスできないことをサーバ側でも保証する構成を想定する。

## PDFローカルキャッシュ

本番では、同じPDFを開くたびにクラウドから取得しない構成を検討する。

```text
初回：StorageからPDF取得 → Webアプリ内部のローカル領域へ保存
2回目以降：ローカルPDFを利用
```

通信量の削減、PDF表示速度の向上、通信環境が不安定な店舗での利用性向上を目的とする。PDFをiPadのFilesアプリへ通常のPDFとして保存する方式にはしない想定である。

## オフライン閲覧

一度取得したPDFを店舗iPad等でオフライン閲覧可能にすることを検討する。候補技術はPWA、Service Worker、Cache Storage、IndexedDBである。

```text
オンライン：認証 → PDF取得 → アプリ内部へ保存
オフライン：アプリ内部のPDFを表示
```

## PDF更新・バージョン管理

各PDFに `version` または `updated_at` 等を持たせる想定である。

```text
ローカルPDF → サーバ側の最新情報を確認
同じ         → ローカルPDFを利用
更新あり     → 最新PDFのみ取得 → ローカルPDFを置き換え
```

## ログイン状態保持

店舗スタッフが毎日ログインしなくても利用できるよう、初回ログイン後は一定期間認証セッションを保持する想定である。

ただし、セッション期限切れ、パスワード変更、アカウント停止、一定期間オンライン認証できない場合等には再認証させる。具体的な保持期間は今後決定する。

## 本番運用で追加検討する項目

本番化までにVEXUM社内およびINSOU側と以下を検討する。

- Vercel / Supabaseの正式採用
- 契約アカウントの所有者
- INSOU / VEXUMどちらが費用を負担するか
- データ所有者、契約終了時のデータ移管
- バックアップ、障害監視
- 操作ログ、アクセスログ
- 保守運用体制
- パスワード変更運用
- ストレージ容量、通信量
- セキュリティレビュー
